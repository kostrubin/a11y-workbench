2. THE PRODUCT TO DELIVER

Create an English-language accessibility workbench for frontend engineers, QA and small maintainers without a dedicated accessibility team. Its immediate value is connecting observed findings to a reproducible interface state, a trustworthy comparison, the remaining manual review and an executable correction.

The main journey is:
Try a synthetic sample -> import a supported report -> inspect findings and outcome counts -> compare compatible baseline/candidate runs -> record clearly user-reported manual checks -> export minimized JSON or Markdown -> inspect the relevant corrected pattern and regression test.

Every part must work without an account. No file upload service or server-side scanning. Processing stays in the browser session. The application itself needs no OpenAI API key, runtime LLM, paid API, database, authentication, telemetry, remote fonts or browser persistence. Build a useful deterministic tool; do not add an AI chat UI or incur per-visitor inference costs.

P0 has exactly three interactive patterns: form validation, modal dialog, and single-level action menu. Each has an intentionally broken and corrected variant, clear explanations, runnable tests and manual checks. Corrected is the default. Deliberate failures live in controlled fixture surfaces with a dependable outside reset/exit; do not make the workbench shell inaccessible in the name of demonstration.

Required named states are forms.initial, forms.invalid, forms.success, dialog.closed, dialog.open, dialog.saved, menu.closed, menu.open and menu.selected. The localhost CLI ships as part of P0 and captures the bundled synthetic recipes. It is optional for a visitor to run. P0 documents adaptation to one's own app but does not execute arbitrary imported adapters or remote scanning recipes.

4. REPORT AND COMPARISON CORRECTNESS

Implement the executable schemaVersion "1.0" contract, including validation, additionalProperties:false at canonical boundaries, documented caps and explicit failure states. Treat all files as untrusted data. Support the defined raw axe JSON shape and canonical bundle; do not pretend to import arbitrary Playwright HTML reports, trace ZIPs, every axe format or future schema versions.

Preserve violations, incomplete results, passes and inapplicable counts separately. Incomplete means needs review. Missing information remains unknown. An empty result is not proof that a scan completed. Rule counts and affected-node counts are different quantities and must be labelled correctly.

Use stable opaque explicit subject IDs where available, otherwise the specified namespace-scoped HMAC identity mechanism. Browser identity keys remain memory-only; do not export them. Never match by accessible name, user value, array position, approximate selector similarity or URL. Unknown identifiers may be shown as escaped text but do not invent trusted descriptions or links for them.

Compare per state only with compatible capture metadata. A list of executed rules and a list of observed subjects do not by themselves prove that a particular rule evaluated a particular subject. Use capture.evaluatedPairs as specified. "Newly detected" and "Not detected in this run" require an actual corresponding pass for the exact rule/subject in the opposite comparable run. Missing states/elements, incomplete checks, namespace changes, changed engine/rules/scope/environment, partial captures and insufficient evidence must not manufacture improvement.

Expose the five canonical comparison categories: persisting -> Still detected; changed -> Changed; new -> Newly detected; not-detected -> Not detected in this run; unassessable -> Cannot assess. Explain the reason in the interface. Raw axe imports without adequate provenance remain useful for inspection and descriptive side-by-side views; do not promise a trustworthy regression verdict when the input cannot support it.

Manual checks start not-run and are distinct from automation. Support pass/fail/not-applicable with local observation/reason as specified. Notes and tester context stay session-only and are excluded from P0 exports. Reimported manual statuses remain explicitly user-reported with observation details absent. Never mark a human screen-reader session as performed because automated focus or axe tests passed.
