# Security and privacy requirements

## Trust model and approval boundary

P0 processes accessibility reports locally and optionally inspects a trusted application on an explicitly selected loopback origin. Browser-local processing reduces server exposure; it does not make malicious files, dependencies, browser extensions, downloaded reports, or the inspected page safe. The application makes no anonymity, compliance, penetration-testing, or complete-accessibility guarantee.

The project owner approves changes to spending, security boundaries, sensitive-data policy and website/product release. Routine user operations already designed into the product—selecting a local report, recording a local observation, exporting minimized JSON/Markdown—do not require the owner's approval for each file. Development and demonstrations use synthetic fixtures. Introducing uploads, remote target scanning, authentication, telemetry, public report sharing or retention of additional sensitive fields changes this policy and requires owner approval before implementation or activation.

The owner explicitly authorizes the public `kostrubin/a11y-workbench` repository to contain reviewed project source, documentation, tests and synthetic examples. Keep that repository public. Inspect the exact files and prepared commits before ordinary commits/pushes to a working branch; do not force push or bypass branch protection. Never publish secrets, credentials, real user reports, personal data, browser profiles or sensitive logs. Retain MIT for original code and required third-party license notices. This source authorization does not grant website deployment, public previews, GitHub Releases, package publication, website indexing or additional spending. The dedicated Codex Cloud environment remains private / `Only me`.

## Untrusted input stays data

Every imported byte is untrusted, including canonical-looking reports and files generated by our CLI. File extensions and MIME types are hints, not validation. Enforce the byte, depth, string, node and time limits in [ARCHITECTURE.md](ARCHITECTURE.md) before accepting a report. Use strict UTF-8 JSON parsing; reject malformed JSON, invalid shapes and unsupported versions. Never use `eval`, `Function`, executable revivers, imported modules, JSONP, YAML tags, or configuration scripts to load a report.

Walk parsed objects iteratively. Reject `__proto__`, `prototype` and `constructor` property names anywhere in imported structures. Construct allowlisted canonical records without prototype-affecting merges or assigning attacker-supplied keys to ordinary objects; use Maps for dictionaries. Do not execute an imported CSS selector or regular expression. Selector arrays are transient input to the fingerprint function only. Resource limits apply even to fields that will be discarded.

Render all imported identifiers through React text nodes or `textContent`. Imported strings must never reach `innerHTML`, `dangerouslySetInnerHTML`, inline scripts/styles, CSS selectors, Markdown-with-HTML renderers, iframe `srcdoc`, or event handlers. A string that looks like HTML remains visible text or is rejected by the identifier schema. This follows [OWASP DOM XSS guidance](https://cheatsheetseries.owasp.org/cheatsheets/DOM_based_XSS_Prevention_Cheat_Sheet.html).

Ignore imported `helpUrl`, image URLs and links. Build documentation links from the bundled trusted rule catalog; validate the permitted HTTPS destination in that catalog. Unknown rules have no auto-generated external link. Opening a trusted external reference is a deliberate user action, with `noopener` and `noreferrer`; never prefetch it using report content. User-controlled URL fragments or search parameters cannot load a report, trigger scanning or restore private state.

## Collection, retention and export

The application has no report upload endpoint, analytics SDK, remote error reporter, remote fonts, image proxy, runtime LLM or external content request. Serve application resources locally/from the chosen static origin. Import, filtering, comparison, checklist updates and export require no report-dependent network request; preloaded or lazy-loaded same-origin application assets are permitted. Browser tests must observe this property rather than rely on a privacy statement. A future host may record ordinary static-page requests; do not describe that as “no data ever leaves the device.”

Raw reports remain transient and are never written to IndexedDB, localStorage, caches, service workers, console logs or error messages. P0 does not persist normalized reports or browser identity keys either. Discard raw references after normalization or cancellation. JavaScript cannot promise forensic memory erasure; document that limitation without claiming secure deletion. Do not retain source filenames. “Clear workspace” removes normalized session data, observations and identity keys, clears visible state, and revokes outstanding export object URLs. It cannot delete previously downloaded files or defeat a compromised device.

Export is a newly constructed canonical JSON bundle or a generated Markdown summary using the same exact allowlist. It preserves rule/check IDs, safe identities, coverage/configuration fingerprints, categories, severity and user-reported manual status. It excludes DOM/HTML, accessible names, node text, input values, full or partial page URLs, screenshots, stack traces, source messages, notes, filesystem paths, cookies, headers and identity keys. Never serialize a cached raw result or arbitrary React state. Escape Markdown metacharacters; never include imported links, images, raw HTML or untrusted code fences. Only JSON is re-importable. Use a fixed generated filename independent of input. Revoke download object URLs after use.

Display an export preview of fields and counts. Explain that opaque identifiers are still pseudonymous and may reveal project structure; syntactic validation cannot recognize every personal name embedded in a valid alias. Do not claim automatic personal-data detection. P0 has no “include everything” export mode, CSV formula surface or HTML report attachment. Users remain responsible for the files they deliberately share.

## Optional localhost CLI

Require a single explicit URL and output path. No crawling, URL discovery, remote targets, scheduled scans, login, imported credentials/cookies, saved browser profiles, HTTP credentials, CDP connections, arbitrary user scripts or downloaded workflow definitions. State capture configuration is declarative and limited to the implemented P0 synthetic fixtures; never load executable code from an imported report. The documentation may show integration into a developer's own test harness, but the P0 CLI does not execute arbitrary adapter modules.

Report contents cannot choose filesystem paths. Create outputs atomically, reject output symlinks and existing files unless an explicit overwrite option is supplied, and restrict identity-file permissions to the current user where the platform supports it. Never print identity keys or copy them into reports.

Allow only HTTP loopback targets: exact `127.0.0.1`, `[::1]`, or `localhost` with an explicit valid port. Reject userinfo, deceptive suffixes, alternate numeric host spellings, wildcard hosts and non-HTTP schemes. Normalize the literal `localhost` case to a loopback address before connection; do not accept arbitrary DNS names that happen to resolve locally. Only the selected origin is allowed. Paths and query values are transient operational input and never included in logs or output. Redirects and subresources crossing that origin are blocked, including other loopback ports. No proxy settings are inherited into the browser.

Start a fresh ephemeral browser context. Disable service workers, permissions, downloads, popups and WebSockets; reject network methods other than GET/HEAD. Install context-level routing before navigation and re-check every request URL, including redirects and frames. Playwright documents that service workers can hide requests from routing, hence `serviceWorkers: 'block'` is required: [network documentation](https://playwright.dev/docs/network).

Blocked resources, timeouts and failed captures produce a partial/error report and a non-success status, never zero-issue success. Bound navigation to 15 seconds, each state to 30 seconds, and the overall run to five minutes. Close contexts and temporary files in `finally`. Disable screenshots, video, trace/HAR capture and browser-console forwarding by default. Output errors contain reason codes rather than target contents.

Playwright routing is defense in depth, not an operating-system network sandbox. The CLI is for a trusted local application controlled by its operator. It must not claim safe inspection of malicious sites or complete control of every browser transport. Supporting untrusted applications would require a separate isolation design and owner approval. Running page scripts can have application effects. The bundled recipe may activate or submit only the repository's synthetic, local-only fixtures to reach the nine required states; it never performs destructive actions or automatically submits arbitrary forms in a user's application.

## Dependencies, CI and repository data

Pin a compatible tested runtime, package-manager version and lockfile; use reproducible installs. Keep permissions narrow and dependency count modest. No secrets are required for product runtime or ordinary tests. Do not add an API key to solve an implementation problem. `NEXT_PUBLIC_*` values are public build inputs, never secret storage. Exclude local reports, raw fixtures, identity-key files, browser profiles, traces and `.env` files from Git; commit only reviewed synthetic fixtures.

Prepare CI with `contents: read`, explicit timeouts, bounded concurrency and no deploy/publish permissions. Actions should use reviewed full commit SHAs. Use normal `pull_request`/trusted push checks without repository secrets. Do not introduce privileged `pull_request_target` or `workflow_run` processing of untrusted code/artifacts. Never interpolate PR titles, branch names or imported report strings into shell source. GitHub documents these risks and least-privilege guidance in its [secure-use reference](https://docs.github.com/en/actions/reference/security/secure-use).

No package publication, GitHub Release, repository visibility change, public preview, paid runner or deployment is authorized. Keep `SITE_RELEASE_APPROVED=false` and `SITE_PUBLIC_ORIGIN` empty. Repository workflows may be prepared as inactive templates without enabling potentially billable execution. Security controls do not grant authority to bypass an approval gate. Reviewed source commits and pushes in the named public repository are already authorized and do not need repeated approval.

## Machine-testable release requirements

| Case | Required observation |
|---|---|
| HTML/script/event-handler payload in input | No execution, new element, navigation or network call; safe rejection/text only. |
| `javascript:`, `data:`, remote URL in report metadata | No link, request, frame or image is created. |
| Prototype-pollution keys at any depth | Import fails; global/object prototypes remain unchanged. |
| 10 MiB + 1 byte, depth 65, 51 states, 10,001 nodes | Specific bounded failure; existing workspace unchanged. |
| Invalid UTF-8, malformed JSON, oversized raw string, cancelled worker | Safe error; no partial accepted report, raw dump or stuck interface. |
| Synthetic email/password/token/URL canaries in raw axe fields | Absent from normalized export, storage, logs and browser network observations. |
| Import, diff, manual check and export with network monitored | No report-dependent request; no hidden telemetry or external fetch. |
| Clear workspace and reload | P0 session data, observations and identity key disappear; no browser persistence restores them. |
| Engine mismatch, removed state/node, partial capture, missing rule/subject pair | Unassessable where required; inapplicable is not a subject-level pass; never automatic “resolved” or compliance success. |
| Local target redirects remotely or requests another port | Request blocked before connection; capture cannot be reported complete. |
| CLI receives remote/deceptive host, credentials or unsupported scheme | Rejected before browser navigation. |
| CLI page opens popup/WebSocket/download or registers service worker | Blocked; result records any effect on capture completeness. |
| Clean static production export | No API route, secret, raw report, runtime network dependency or deployment side effect. |

Run hostile-input cases against both normalization and browser presentation, not only a validator mock. Use controlled local test servers and synthetic payloads. Report which checks actually ran and any remaining limits; do not mark an unexecuted check passed. Security concerns should be reported privately through the repository owner's configured channel once available, without attaching real reports to public issues.
