Use a menu for actions, not ordinary navigation

A menu promises a particular keyboard interaction. This single-level example performs a local view command; normal website links do not need application-menu roles.

Try the action menu

Open with Enter or Space, move between commands with the arrow keys, try Home and End, then choose a view. Escape dismisses the menu and returns to its button.

What the correction changes

The corrected button exposes aria-haspopup="menu" and its expanded state. Opening moves focus to a menu item. A roving tab stop supports arrow keys, Home and End; selecting an action or pressing Escape returns to the button. Tab exits instead of trapping focus. The selected command is announced as a local outcome.

The broken example omits the expanded/menu relationship and item-navigation behavior. Its ordinary buttons can still be clicked and its outside reset stays available. These failures are not all detectable by axe; keyboard assertions test the promised interaction.

Choose between an action menu and a disclosure.

Verify the behavior

  1. Focus Choose display view and press Enter. Confirm expanded state and focus on Compact.
  2. Use ArrowDown, End, Home and ArrowUp. Confirm that focus moves among the three local commands.
  3. Select a command. Confirm that it is announced and focus returns to the button.
  4. Reopen with Space and dismiss with Escape. Reopen once more and press Tab to leave the menu.

Regression coverage: E2E-09, E2E-10 and corrected-pattern axe checks. Capture states: menu.closed, menu.open, menu.selected.
