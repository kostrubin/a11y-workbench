A dialog needs a predictable way back

Opening a modal changes the active task. Make that context clear, keep background controls unavailable and return focus when the task ends.

What the correction changes

The corrected example opens the native dialog with showModal(). Its heading supplies an accessible name, the input receives initial focus and the browser provides modal containment and background inertness. Cancel, Escape and Save all return focus to the opener. A larger dialog may need a different initial focus target; this short editing task starts at its input.

The intentionally broken version displays an ordinary panel without dialog semantics, modal containment or initial-focus movement. It has a working Cancel button and an outside reset, so the demonstration does not trap visitors. Automated scans alone cannot establish whether a person understands the context change.

Reproduce a dialog-focus failure and test its correction.

Verify the behavior

  1. Focus the opener and press Enter. Confirm that focus lands on Display name inside the dialog.
  2. Cycle with Tab and Shift+Tab. Confirm that focus stays in the modal and background controls cannot be activated.
  3. Press Escape. Confirm that the modal closes and focus returns to its opener.
  4. Reopen, edit the synthetic value and save. Confirm the local update and the same predictable focus return.

Regression coverage: E2E-08, E2E-10 and corrected-pattern axe checks. Capture states: dialog.closed, dialog.open, dialog.saved.
