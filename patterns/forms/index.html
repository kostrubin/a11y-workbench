Make form errors discoverable

An error is useful only when someone can find it, understand it and recover. This local form keeps entered values and connects each correction to its field.

What the correction changes

The corrected version uses explicit labels, instructions, an error summary, aria-invalid and error descriptions. After an invalid submission, focus moves to the summary; each summary link leads to its field. A live region reports local success without moving focus away from the form.

The broken version intentionally replaces labels with unassociated visual text and omits error associations, focus recovery and live success feedback. Its surrounding controls remain usable. An automated label finding describes one defect; keyboard and human checks are still needed to understand error recovery.

Diagnose a field-error association step by step.

Verify the behavior

  1. Submit with both fields empty. Confirm that the summary receives focus and names both errors.
  2. Follow the email error link. Confirm that the email input receives focus and retains its hint and error description.
  3. Enter a synthetic display name and a valid example address. Confirm that the values survive and local success appears.
  4. Repeat in the broken version and record the differences as observations, not an accessibility score.

Regression coverage: E2E-07, E2E-10 and corrected-pattern axe checks. Capture states: forms.initial, forms.invalid, forms.success.
